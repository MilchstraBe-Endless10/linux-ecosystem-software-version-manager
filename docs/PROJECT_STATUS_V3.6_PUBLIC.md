## 已确定的产品方向

- **目标环境**：Omarchy / Arch Linux + Hyprland / Wayland；Linux 原生图形客户端，免费开源为目标，许可证仍待明确。
- **软件范围**：发现本机软件与不同安装实例，优先覆盖 Omarchy/pacman、Flatpak、npm global、pipx、uv tool、pnpm global、Bun global、mise global 的完整更新闭环；加强 AUR、Cargo/rustup 的条件执行。
- **安全默认值**：自动检查与提醒，但系统更新及普通更新执行必须经用户批准；仅合格的指定实例允许显式开启受控自动更新；禁止危险的 Arch 部分升级。
- **GUI 决策**：UI-A 综合工作台、VIS-B 明亮柔和视觉、WB3 自定义网格、DEN-C 自适应密度、COL3 自定义软件清单、DET3 多实例详情、CMP3 差异优先比较、TAG3 自适应五组导航。
- **美术资产**：已批准浅色动漫视觉基准。原始母稿、人物场景素材、视觉截图及未明确再分发许可的资源仅保留在私有开发工作区，**不包含在公开仓库**。
- **技术路线**：Qt 6 + Qt Quick/QML + C++ 为有条件的首选，Flutter 仅保留为独立备选 PoC；尚未冻结架构或决定正式发布许可证。

## 公开仓库与技术验证

本仓库为独立的、经过筛选的**公开开发快照**，不镜像本地私有开发仓库的全部历史。

- 已有 Qt Quick/QML + C++ 的模拟数据原型，支持 10,000 条合成记录的列表压力试验。
- GUI-POC-002 在某次 Wayland 测试环境中获得约 59 FPS 的平均采样；两次不同请求窗口尺寸最终均映射为 941×1030。此数据**不证明**目标尺寸表现已通过。
- 已知待验收：合成器窗口规则和真实尺寸测试、长帧定位、人物/背景完整分层与视觉保真、WB3 指针拖拽、后台降载、TAG3/CMP3 的完整交互、Qt 许可证及美术许可。
- 仓库内的样机数据及按钮仅为模拟；不执行真实包管理器更新。

## Codex 与 DeepSeek Harness（DSH）协作

**Codex 是开发总控**，负责架构设计、UI/QML、视觉和动画、任务拆解、权限控制、代码审查、测试与最终整合。

**DeepSeek Harness 是受控开发执行者**。Codex 应通过 Harness Relay 对其**主动委派**具备明确契约的任务，而不应长期停留在只读审查：

1. Codex 查询当前注册工作区、模型能力及工具权限，不硬编码本机端口或路由。
2. Codex 明确任务契约、允许读取/写入文件、排除路径、测试命令及验收标准。
3. 适合委派的独立模块：版本比较和安装实例身份键、K3 更新来源适配器、模拟数据测试、解析器、故障复现和文档核查。
4. 只读审查使用 `start_review`。**经授权的写入实现**使用 `start_run`，并根据实际工具能力限定 `permissionPreset: "workspace-write"` 与具体写入范围；`workspace-write` 不等于系统管理员权限。
5. Codex 用 `wait_run` 获取任务结果；必要时 `steer_run` / `reply_run` / `cancel_run`。DSH 任务终态不代表 Codex 验收通过。
6. 由 Codex 审查 diff、测试和安全边界；不得并行写同一文件，不得让 DSH 直接修改已批准的视觉母稿或 QML 核心设计，不得执行真实系统升级。
7. 首个合适的 DSH 实现切片为 **VERSION-ID-001**：只针对 mock 数据的版本解析、比较、实例身份键；先由 Codex 确认接口、测试、文件白名单后委派。Qt Quick 视觉问题由 Codex 主导处理。

## 文档持续同步原则

- **公开 GitHub 是已审查文档的主要共享入口**，不要求用户每次下载 ChatGPT Markdown 再搬运。
- 每次 PRD 更新，都应同步产生“公开增量摘要/经审查的公开版”，经敏感信息及授权检查后提交或发起 PR。
- 私有完整 PRD 仍为内部需求资料；不可把工作区绝对路径、Relay 会话、凭证、Soul、会话记忆、未经确认可再分发的动漫素材或截图直接上传。
- 公开内容按 Git commit/PR 保留修改历史；避免在没有审查的情况下强制覆盖已有文档。
- Codex 在本机进行正常开发时，应先拉取或对照公开文档变更，注意公开快照与私有开发历史**不相同**，不得盲目合并仓库历史。
